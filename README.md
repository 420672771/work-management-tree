# 工作管理树（V1.2 MVP）

正式用户的登录、初始密码和日常操作说明见[工作管理树用户操作手册](docs/工作管理树用户操作手册.md)，登录后也可访问站点的 `/manual` 在线阅读或下载。

手册含 16 张带编号的实际页面截图和 7 张流程图，在线支持点击放大及打印 / 保存图文 PDF。配图使用隔离环境中的虚构资料，更新方式见[手册配图说明](static/manual-assets/README.md)。

本次生产发布请先阅读[生产发布与基础资料迁移](docs/生产发布与基础资料迁移.md)。正式基础资料已通过[仓库内的加密迁移包](deploy/migrations/README.md)交付，例行演练资料不迁移；原始数据库、解密密钥和实际环境配置不进入代码仓库。拉取代码后须解密安装并切换实际数据库路径，不能只启动空库。

面向科技产品中心的管理树与任务闭环系统：管理树描述长期责任边界，任务只有一个最终责任人，责任人自行组织内部协同。

## 本地运行

```bash
cd /home/admin/work-management-tree
python3 app.py
```

打开 http://127.0.0.1:8080 。数据库默认写入 `data/worktree.db`，可用 `WMT_DB` 覆盖。

当前测试服务支持一次启用后端自动重载，以后修改 Python 源码无需逐次手工重启。启用与关闭方法见 [部署说明](deploy/README.md)。前端页面、样式和脚本更新刷新浏览器即可生效。

也可用可重复启停脚本部署：

```bash
chmod +x scripts/*.sh
./scripts/start-local.sh
./scripts/healthcheck.sh
./scripts/stop-local.sh
```

临期/超期提醒可由本地计划任务执行（同一天、同一任务、同一提醒类型幂等）：

```bash
python3 scripts/send-reminders.py
```

## 企业微信配置

设置 `WECOM_CORP_ID`、`WECOM_AGENT_ID`、`WECOM_SECRET` 后，系统可通过 `/api/notify` 发送应用消息；未配置时只记录 dry-run 日志，不会误发消息。设置 `WECOM_TOKEN` 和 43 位 `WECOM_AES_KEY` 后，将企业微信应用“接收消息” URL 配置为 `/wecom/callback`，员工可发送 `任务#123 已完成/预计周五` 回写任务反馈。

AI 草稿默认使用规则解析。若配置兼容 OpenAI Chat Completions 的 `AI_API_BASE`、`AI_API_KEY`、`AI_MODEL`（例如企业批准的模型服务），则优先调用模型；模型错误时会安全回退为规则草稿，且始终要求 PM 人工确认。

## 责任域维护

“组织配置 → 责任域维护”支持部门负责人和管理 PM 自定义责任域，维护名称、编码、负责人、所属条线及责任边界。新增时可选择部门节点或已有责任域作为上级；新责任域会出现在任务、草稿和例行模板的选择项中。

列表显示引用情况。已被任务（含完成、取消和草稿状态）、例行模板（含停用）、任务草稿、下级节点、历史报表或历史业务记录引用的责任域不能删除，仍可修改。删除时服务端会再次检查，引用限制也覆盖任务写入与删除并发的情况。

修改名称后，当前任务和模板按原责任域编号显示新名称，历史周报、月报的责任域标签及系统生成的月报分组同步更新，包含已发布和已归档版本。任务归属、状态、工时、报告统计和人工总结不被重新计算或替换；历史修改记录保留在审计日志。打开旧草稿尚未保存的客户端会收到版本冲突提示，重新加载后再编辑。默认责任域只在首次初始化时建立，服务重启不会覆盖维护结果或重建已删除的默认责任域。

## 部门周报

“部门周报”菜单仅部门负责人和管理 PM 可见。默认在北京时间每周日 18:00 自动生成“科技产品中心部门工作总结报告”，周期为周一至周日；快照只纳入科技产品中心已确认的正式任务，排除草稿和已取消/删除任务。

- 提供新增、完成、进行中、逾期、待验收、完成工时和责任域覆盖统计，可展开对应快照任务。
- 自动整理重点成果、风险及下周重点，任务默认按编号升序排列；责任域保留在任务信息中，不再分组。待验收超过 48 小时列入关注项。
- 重点工作与成果仅纳入未完成的 P0 正式任务，以及本周已完成的任意优先级任务；不再以验收、标准工时或复杂度作为入选条件。
- 打开菜单直接查看本周最新报告，缺少时自动补生成。负责人和 PM 可编辑摘要、总结、条目说明及排序，修改自动保存；统计数字不能手工修改。
- 日常只保留“待发布 / 已发布”两种状态，无需单独保存或开始审阅。负责人一键发布，系统会先完成最后一次自动保存；保存失败或编辑冲突时保留输入并阻止发布。
- “更多操作 → 更新任务数据”在同一待发布草稿内刷新快照，保留人工摘要、总结、有效任务说明及已有排序，并提示新增、移除和变化项。更新前的草稿快照留在审计日志中。
- 已发布版本保持只读，负责人点击“修订”会建立保留原快照和人工内容的独立草稿；再次点击会打开已有修订稿，避免重复建版本。历史页提供版本查询。
- 首页提示负责人审阅待发布报告；支持按年/月/ISO 周次查询历史，以及复制会议材料文本。

统计按快照生成时可见的正式任务数据计算。页面会提示后续任务变更，点击“更新任务数据”后才会纳入。周日定时生成会刷新提前补生成的待发布草稿，并保留人工编辑；已发布版本始终保持只读。完成时间优先取验收通过或 100% 进度确认时间，无事件记录的历史任务使用更新时间；报告会注明这一规则。标准和实际工时只汇总本周完成任务，不自动评价人员。

自动生成程序可单独运行（不发送飞书消息）：

```bash
python3 scripts/generate-weekly-report.py
```

部署时启用定时器的步骤见 [部署说明](deploy/README.md)。程序会补生成停机期间最近一个应生成周期；同一周期重复执行不会覆盖人工审阅内容。PDF 排版、跨部门汇总及复杂审批暂未纳入首期。

## 科技产品中心智能助手：对话维护资料与任务

飞书长连接与 HTTP 回调共用对话处理流程，按飞书绑定的真实成员身份检查权限。负责人和管理 PM 可通过对话新建部门、岗位、成员、责任域/子责任域和每周例行任务模板；修改成员姓名、部门、角色、登录账号、主岗位、直属上级与确认人。任务责任人、负责人和管理 PM 可修改和删除有权管理的任务，支持一次调整多个字段。说“助手帮助”可查看完整示例。

任务修改支持多轮补充：例如“修改任务15的责任人”会追问新责任人，随后直接回复姓名即可生成待确认操作；单独回复“#15”也能接续上下文。缺少任务编号、新日期或修改内容时只追问缺少的参数，不直接执行。补充内容按用户及会话隔离，10 分钟内有效；确认时仍复核权限和任务是否变化。

新建任务同样支持多轮补全。先发事项再回复“这是一条新增任务”时，会沿用前文生成草稿；单独回复日期、责任人、优先级或补发任务情况会更新同一份草稿。意图不明确时先询问新建还是更新，缺少字段时只追问缺失信息。默认责任人为本人，草稿会明确回显；正式生成仍通过网页确认中心。回复“取消”会放弃当前草稿，明确提出另一条新任务会开启另一份草稿。

`assistant_dialogue.py` 在模型理解阶段提供同一用户、同一会话最近 10 分钟的最多 8 条对话、当前草稿及缺失字段；模型只返回受限字段建议，既有权限校验和变更确认继续由后端执行。模型不可用时继续保留草稿并追问，单轮不会因失败反复调用其他模型路径。`audit_log` 中 `object_type='assistant_model'` 的 `dialogue_ok/dialogue_unavailable` 记录模型名、意图和耗时，不写入密钥或模型异常原文。启动时自动增加 `bot_dialogue_turn` 表，无需重新导入基础资料；部署后须重启网页和飞书消息接收进程。

```text
新建部门 数据产品部
新建岗位 数据分析师，部门：数据产品部
新建成员 张三，部门：数据产品部，岗位：数据分析师，账号：zhangsan
修改成员 张三，直属上级：部门管理PM，角色：普通成员
把张三的部门改为科技产品中心
新建责任域 数据治理，负责人：张三，边界：数据质量管理
新建例行任务模板 每周数据检查，责任域：数据治理，责任人：张三，标准工时：2，交付物：检查记录
新建例行任务模板 每周例行检查，责任域：数据治理，责任人员：张三、李四，标准工时：2，交付物：检查记录
任务#15 优先级改为P0，交付物改为评审纪要
删除任务#15
```

缺少资料时可继续补充，例如“新建岗位 数据分析师”后回复“部门：数据产品部”。操作先回显内容，回复“确认”才执行、“取消”放弃，10 分钟内有效；待执行内容按会话和成员隔离。重名对象使用 `#编号`。确认时重新检查权限、引用资料与任务版本，变更已发生时要求重新提出；重复确认不会重复执行，失败完整回滚，成功写入审计日志。姓名与账号变更不会覆盖已有密码，首次配置账号使用现有初始密码规则。例行任务的标准工时快照和验收规则保持有效。

有模型配置时，可辅助提取更自然的资料维护表达；模型提议仍须通过字段白名单、真实资料引用、权限和对话确认。HTTP 事件须提供有效的 `FEISHU_VERIFICATION_TOKEN`，长连接通过飞书 SDK 接收认证事件。修改后端或 `scripts/feishu-long-connection.py` 后，应重新加载应用并重启飞书长连接服务，使两个入口均运行新版逻辑。

## 账号登录与个人中心

登录入口为 `/login`，测试主站右上角也提供“账号登录”。账号配置在“组织配置 → 岗位与成员”：负责人或管理 PM 新建/编辑员工时设置登录账号和初始密码，成员卡片提供“重置密码”。账号不区分大小写；密码为 6—128 个字符，只保存加盐哈希，不返回或回显原密码。新账号默认初始密码为 `123456`，首次配置账号时密码留空也使用该初始密码；已有账号的密码留空表示保持原密码，不会批量覆盖已有账号密码。

登录后点击右上角“个人中心”，可查看本人资料、修改密码、扫码绑定本人飞书。绑定后可从登录页使用“飞书扫码登录”。账号密码与飞书使用同一员工身份；密码修改会保留当前新会话，注销其他会话，管理员重置密码会注销该员工全部旧会话。连续错误登录会暂时限制尝试。

- 当前测试环境继续使用 `WMT_AUTH_MODE=demo`、`WMT_MONTHLY_DEMO=1`，可切换负责人/PM 演示身份配置账号，也可真实登录验证个人中心与权限。
- 正式环境使用 `WMT_AUTH_MODE=account`（兼容 `feishu`），关闭演示开关后必须登录。飞书凭据和回调配置齐全时，两种方式均可从登录页进入。
- 首次正式部署可先在服务器终端为已有负责人配置账号：`python3 scripts/set-user-account.py --user-id <负责人ID> --username <账号>`。密码通过隐藏输入读取，不放在命令参数中。自定义数据库时使用与网站相同的 `WMT_DB`。
- 飞书扫码仍需配置有效回调地址并登记到飞书应用后台，见下文“飞书扫码登录”；未配置时账号密码登录可正常使用，扫码按钮显示配置状态。

## 员工个人月报

一级菜单“个人月报”提供按月生成、自动保存、归档及历史版本查看。每位员工仅能生成、编辑和归档自己的月报；部门负责人和管理 PM 可通过“部门月报”查询全部员工月报，查看他人月报时只读。

- 以本人已确认的正式任务生成六个思维导图分支：月度概览、重点工作与成果、任务进展、风险与阻塞、下月计划和工作总结。月份按北京时间计算，当前月份统计到生成时刻；已结束月份统计到月末。
- 重点工作纳入未完成 P0 和本月已完成的全部优先级任务；下月计划纳入下月到期的未完成任务，以及正在推进的 P0/P1 任务。草稿、待确认、取消和删除任务不纳入。
- 所有导图节点（含标题、统计和主分支）均支持删除、增加子节点及同级上移/下移，首尾位置按实际顺序限制移动；删除会同时移除子节点。支持添加顶层节点，清空后可重新编写。统计数字、本人姓名与月份的节点文字仍取自任务快照；其他节点文字可编辑。采用绿色主题节点、向右展开的灰色曲线与文字下划线样式；长文本完整换行。默认收起编辑区，白底画布可滚动，支持阅读大小、适应宽度、全屏查看、平移缩放、折叠展开、SVG 导图导出、导图 JSON 导出和复制文本。
- 修改自动保存；归档会先保存最后一次输入，固定任务快照和导图。归档后不可直接修改，可新建修订稿，保留原版本。再次生成同一月份会打开已有版本，不覆盖人工内容。生成后任务变化不会自动改写月报。
- 测试环境可设置 `WMT_AUTH_MODE=demo`、`WMT_MONTHLY_DEMO=1`，直接通过顶部演示身份切换员工，使用生成、查看、编辑、自动保存、归档、修订及导出；这些操作写入测试数据库。切换前先保存当前输入，保存失败时保持原身份。
- 正式环境关闭演示开关（`WMT_MONTHLY_DEMO=0`），使用已有飞书登录和账号绑定。服务端始终优先采用真实登录会话，飞书登录模式下演示开关无效；客户端身份不能覆盖登录员工。登录配置见下文“飞书扫码登录”。

### 飞书扫码登录

系统支持把已绑定的飞书成员作为登录账号。启用前需确定用户浏览器实际访问的固定地址，并在飞书自建应用中开启网页应用能力，将完整回调地址登记到“安全设置 → 重定向 URL”。推荐使用 HTTPS 域名；内网 HTTP 地址也须与实际访问的协议、主机及端口一致，例如 `http://192.168.1.197:8080/auth/feishu/callback`。域名示例：

```text
https://你的域名/auth/feishu/callback
```

服务环境变量：

```bash
WMT_AUTH_MODE=account
WMT_PUBLIC_BASE_URL=https://你的域名
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
```

登录页只提供一个“飞书扫码登录”按钮，点击后始终在窗口中显示二维码，使用手机飞书“扫一扫”并确认。即使浏览器记住了飞书账号或桌面客户端已经登录，也先扫码；不再根据飞书网页单点登录状态自动跳到授权界面。扫码后飞书仍可能要求确认应用授权，此时核对本人账号后继续。登录与绑定完成后，原页面自动进入工作台或返回个人中心；取消、未绑定等结果也会返回原页面提示。浏览器拦截弹窗时，页面会提示允许后重试；二维码窗口支持刷新和过期提示。

二维码窗口使用[官方 QR SDK](https://open.feishu.cn/document/common-capabilities/sso/web-application-sso/qr-sdk-documentation)及配套的早期 OAuth 授权、token 和 userinfo 接口。扫码前窗口停留在本站，只有收到来自当前二维码 iframe、精确飞书域名且格式正确的扫码消息后才进入授权流程。服务端保存一次性 state、窗口通知标识和绑定时的用户会话，回调通过校验后才通知原页面。通知仅包含固定站内结果地址，不传授权码、token 或用户身份；原页面核对通知标识、来源及实际登录会话，兼容飞书页面切断 `window.opener` 的情况。

对已配置真实飞书应用的本地测试服务，可设置 `WMT_LIVE_FEISHU_URL=http://127.0.0.1:5100`，运行 `node tests/feishu-qr-live.browser.cjs` 检查单按钮及窗口中的真实二维码（需安装 Playwright）。此检查使用全新浏览器会话，不模拟飞书响应，也不会扫码或授权账号；手机确认及真实账号授权仍需人工验收。

员工先使用账号密码登录，再在“个人中心”中扫码绑定；也可由负责人/PM 在“飞书成员绑定”中维护。一个飞书账号只能绑定一位员工。回调校验一次性 state、发起浏览器和绑定时的登录会话；重新发起登录会使该浏览器上一个 state 失效，未绑定账号不会自动创建员工。会话有效期为 8 小时，通过 HttpOnly Cookie 保存。

`/api/auth/options` 的 `feishu_ready` 为 `true` 才表示网页进程的凭据与回调配置齐全。修改 Docker Compose 的 `.env` 后需执行 `docker compose up -d --force-recreate worktree` 重新创建容器；直接运行 Python 时，需将变量注入进程环境，程序不会自动加载 `.env`。本功能继续使用原 `/auth/feishu/callback`，无需新增回调地址，也无需迁移业务数据。

如使用 Cloudflare Quick Tunnel：先启动带认证的本地服务，再运行 `scripts/start-cloudflare-preview.sh`。Quick Tunnel 适合临时验证，无固定域名和 uptime 保证。

### 多员工个人月报演示

运行 `python3 scripts/demo-monthly-report.py` 后访问 `/monthly-report-demo`（“个人月报”登录提示内也提供入口）。演示包含 5 位虚构员工、6 份月报版本及负责人/管理 PM 视角，覆盖完成、进行中、逾期阻塞、待验收、无任务、归档及修订。生成程序使用独立演示数据库；网页复用实际月报界面，后续编辑只保存在当前浏览器标签页，不访问线上个人月报。
