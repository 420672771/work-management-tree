# 工作管理树 V2.1 未完成功能设计

## 目标与边界

在已上线的“管理树 + 唯一责任人 + 任务/进度确认 + 飞书文字建单”基础上，完成试点所需的组织配置、飞书效率闭环和多模态建单能力。

不改变以下原则：

- 一个任务仅有一名最终责任人；协同成员由责任人自行组织。
- 任务创建、进度生效都保留确认与审计记录。
- AI、语音、文档只生成可编辑草稿，绝不直接生成正式任务。
- 飞书长连接为事件入口；网页为管理、确认和追溯入口。

## 一、组织岗位、汇报线与代理

### 用户流程

1. 管理员维护部门、岗位，并将成员关联到主岗位。
2. 管理员为成员维护直属上级和默认确认人。
3. 确认人休假时，设置有开始/结束时间的“确认代理人”。
4. 新任务及进度提交时，系统按“明确确认人 → 直属上级 → 部门负责人”解析确认人；在代理有效期内将确认事项转给代理人。

### 数据与验收

- 使用 `org_position`、`user_position`、`reporting_line`、`delegate`；配置变更写入审计日志。
- 代理范围第一期限定为“确认代理”，不转移任务责任。
- 已创建的待确认事项不自动换人；新建事项按当前有效关系解析。
- 可在组织配置页查看当前岗位关联与有效代理。

## 二、任务类型与例行任务

### 用户流程

- 专项、临时任务由网页或飞书草稿创建；例行任务由模板按日/周生成。
- 所有类型复用唯一责任人、交付物、截止日期、确认和审计能力。

### 验收

- 例行模板可创建、查看、幂等生成；专项/临时任务可筛选展示。
- 例行任务不会因重复执行调度而重复生成。

## 三、飞书输入与既有任务进度

### 文字消息规则

1. 默认：消息被识别为新任务草稿，进入确认中心。
2. 明确引用任务编号时，例如“任务#14 完成 60%，阻塞：等待数据”，识别为该任务的进度填报，生成进度确认事项。
3. 无法确定任务或百分比时，机器人仅提示所需业务信息，不暴露系统字段名。

### 语音与文档

- 接收飞书音频、文件/文档消息后创建“待解析草稿”，保存消息标识和原始材料引用。
- 当飞书文件下载权限及企业认可的转写/文档解析服务配置完成后，自动提取文本并复用文字草稿流程。
- 未配置解析服务时，机器人明确提示“已收取材料，待转写/提取后确认”，不伪造解析结果。

### 验收

- 已绑定成员发送带任务编号的文本，可在确认中心看到对应进度确认事项。
- 新任务与进度均保留原始消息、识别结果、确认记录和操作者。

## 四、晨间清单、晚间提醒与超时处理

### 规则

- 每个工作日 09:00：向有当日重点/临期/逾期任务的已绑定成员发送晨间清单。
- 每个工作日 17:30：向未填报重点任务进度的成员发送填报提醒；生成未填报记录。
- 每日 18:00：提醒待确认人处理确认事项。
- 进度确认超过 24 小时：按当前试点规则自动生效，并写明“超时自动生效”；后续可升级为逐级催办。

### 交付方式

- 通过系统用户定时器执行，业务逻辑幂等。
- 发送成功、失败、跳过均写入通知日志；无飞书绑定者只记录待处理，不尝试发送。

## 五、试点验收与两个月运行

### 指标

- 任务入库完整率：责任人、截止日期、交付物齐全率 ≥95%。
- 日重点任务填报率、确认及时率、逾期率、自动生效次数。
- 每周复盘：新增责任域、无效模板、误识别草稿、提醒触达失败。

### 分批实施顺序

1. 组织岗位与代理、确认人解析。
2. 飞书既有任务进度识别；晨晚提醒的真实投递和定时器。
3. 文档/语音材料接收、可配置解析适配器。
4. 试点看板、运行手册与两个月复盘机制。
