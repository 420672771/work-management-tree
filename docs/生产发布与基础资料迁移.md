# 生产发布与基础资料迁移

本次采用“仅迁移正式基础资料”的范围。不要直接复制测试站的 `data/worktree.db` 到生产，也不要在原数据库上删除演练资料。先生成独立迁移包，复制到生产数据目录后再首次启动服务。

**运维交付入口：**最新完整资料包已加密纳入代码仓库，文件为 `deploy/migrations/production-base-20261109.wmt`。拉取代码后，按[资料包解密与安装说明](../deploy/migrations/README.md)核验并安装到候选数据库，再明确切换运行服务的 `WMT_DB`。解密密钥通过独立渠道交付，不进入 Git。仅拉取代码或启动服务不会自动导入资料。

## 迁移范围

保留正式员工及编号、登录账号及原密码哈希、当前飞书绑定、部门、岗位、有效及未来任职、汇报/确认关系、委托、责任树及责任域、正式例行模板和绩效参数。原有账号密码继续有效，不统一重置；初始密码和修改方式见[用户操作手册](工作管理树用户操作手册.md)。

排除 `routine.*` 演练账号，以及名称或标题带 `[例行演练]`、`演练·`、`[自动测试]`、`[演示]` 前缀的资料。按明确标记识别，不会因为普通业务名称包含“演练”二字而删除。正式模板同时选择正式员工和演练员工时，仅保留正式员工并记入导出报告。正式汇报关系、责任域负责人等引用被排除人员时，导出中止，需先修正正式资料。

本范围不包含任何任务、任务实例、工时、反馈、周报、月报、草稿、审计历史、通知记录、消息队列或旧登录会话；因此正式和演练的历史业务均不进入新库。若生产需要历史业务数据，应另行确认迁移范围，不使用本基础资料包代替历史迁移。

## 在测试服务器导出

在项目目录运行：

```bash
python3 scripts/export-production-base.py \
  --source data/worktree.db \
  --output data/production-migration/20261106/production-base.db
```

脚本通过 SQLite 只读连接制作一致性快照，只升级快照，不修改源数据库。输出路径已存在时拒绝覆盖；重新导出请换目录或文件名。

同时生成 `production-base.db.report.json`，记录各表数量、排除数量、模板名单调整及完整性检查结果。数据库与报告权限均为 `600`，新建目录权限为 `700`。原始数据库包含账号密码哈希及绑定信息，不能直接提交 Git。`data/production-migration/` 已加入忽略规则；公开仓库只交付加密包，密钥和解密后的文件单独保管。

## 生产安装顺序

1. 拉取已提交的代码。已有生产服务时先停止网站、飞书长连接和各定时任务，并使用 SQLite 备份接口备份现有生产数据库及环境配置。已有正式业务的生产库不能被本初始化包覆盖。
2. 单独复制迁移数据库和报告到生产服务器。在首次启动前，将数据库安装到 `WMT_DB` 指定的路径；默认是项目 `data/worktree.db`。确认该路径尚不存在，数据目录可由服务账号写入，数据库可由服务账号读写。不要同时复制测试站的 `-wal`、`-shm` 文件。
3. 由 `.env.production.example` 创建生产配置，填入实际 HTTPS 地址和必要凭据。使用 `WMT_AUTH_MODE=account`、`WMT_MONTHLY_DEMO=0`，关闭开发自动重载。环境文件和凭据不提交 Git。
4. 启动服务，核对 17 名正式员工、6 个岗位、5 个责任域及汇报关系，确认无 `routine.*` 账号和 `[例行演练]` 岗位。使用迁移保留的负责人账号从 `/login` 登录，再核查普通员工权限、在线操作手册和基础资料维护。
5. 完成真实飞书绑定、回调和助手权限核查后启动长连接。按[部署说明](../deploy/README.md)安装例行任务、周报和提醒定时器，确保网站、长连接和定时任务使用同一个 `WMT_DB`。生产定时器不要指向测试库。

`WMT_PUBLIC_BASE_URL` 必须替换为实际生产 HTTPS 地址。需要飞书扫码时，在应用后台登记完全一致的回调地址，并配置实际的 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 和验证令牌；保留已有绑定不代表凭据和回调已配置完成。未配置飞书时仍可使用账号密码登录。

### Docker Compose

在生产项目目录创建 `.env` 并完成上述数据库安装后执行：

```bash
cp .env.production.example .env
# 编辑 .env，填入实际生产配置；不要覆盖已有生产环境文件。
docker compose config --quiet
docker compose up -d --build
docker compose logs --tail 100 worktree
```

Compose 将 `./data` 挂载到 `/app/data`，明确使用 `/app/data/worktree.db`。端口只绑定 `127.0.0.1:8080`，通过 Caddy/Nginx 提供实际 HTTPS 入口。镜像不包含 `.env`、本地数据库、日志、演练报告或截图；应用默认使用真实账号登录。环境配置通过 Compose 的 `env_file` 注入。

直接运行 Python 或 systemd 时，配置必须注入进程环境；应用不会自动加载 `.env`。systemd 使用 `/etc/worktree/worktree.env`，安装路径和数据库路径需与实际服务器一致。Docker Compose 仅包含网站服务，飞书长连接和定时任务须另行配置。

## 验证和恢复

导出会执行 SQLite 完整性及外键检查，并确认运行态与业务数据为空。生产首次启动会自动升级表结构；不会恢复已排除的演练账号、岗位或模板。

上线前运行 `python3 -m unittest discover -s tests -v`，其中 `tests/test_production_base.py` 覆盖资料筛选、密码及绑定保留、源库只读、旧表结构快照升级、重启无演练资料及禁止覆盖目标。

需要恢复时，先停网站、长连接和定时任务，恢复匹配版本的生产数据库备份、代码及环境配置，再启动并验证。不要把生产运行后的数据与初始化包混用，也不要将测试库当作生产备份。
