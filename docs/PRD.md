# MVP 产品需求基线

## 核心规则

1. 一个任务只有一个最终责任人。
2. 责任人自行组织内部执行和协同，管理者只追最终责任人。
3. 责任树描述长期边界，任务描述阶段性交付。
4. AI 只生成待确认草稿，不直接入树。
5. 完成必须经过验收；驳回必须填写原因。
6. 工作状态、时间状态、风险状态分离。

## 状态

- 工作：草稿、待确认、已指派、已接单、进行中、待验收、已完成、已取消。
- 时间：正常、临期、超期。
- 风险：正常、有风险、已阻塞。

## MVP 用户流程

例会/指令 → AI 草稿 → PM 校对 → 指定责任人 → 接单 → 反馈 → 提交完成 → 验收 → 关闭或驳回。

## 非目标

复杂 RACI、公开排名、自动绩效评分、全自动入树、多部门推广和默认自动验收不属于本 MVP。
